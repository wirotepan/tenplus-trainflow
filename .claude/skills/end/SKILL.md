# /end — ส่งมอบให้ session ถัดไป (อัปเดต resume note + HANDOFF)

เป้าหมาย: ทำให้ session หน้า (คนหรือ AI) เปิดมาแล้ว **รู้ทันทีว่าอยู่ตรงไหน / ทำต่อยังไง**
โดยอัปเดตเอกสารกลาง ไม่ใช่ฝากไว้ในความจำ. ผู้ใช้ไม่ถนัด terminal — **รันคำสั่งให้เอง**.

## 1. รวบรวมสิ่งที่ทำใน session นี้
- ดู `git log --oneline -15` (commit ล่าสุด) + `git status --short` (งานที่ยังไม่ commit).
- ทวนบทสนทนา: ทำอะไรเสร็จ, ตัดสินใจอะไรสำคัญ, เหลืออะไรค้าง, verify ไปแค่ไหน.
- **แปลงวันที่ relative เป็น absolute** (เช่น "วันนี้" → วันที่จริง) ก่อนเขียนลงไฟล์.

## 2. อัปเดต `CLAUDE.md` (ส่วน "📍 มาถึงไหนแล้ว / ทำต่อตรงไหน")
- แก้ `อัปเดตล่าสุด: <วันที่จริงวันนี้>`.
- เพิ่ม/ปรับ bullet ✅ ของงานที่เพิ่งเสร็จ (โมดูล/ฟีเจอร์ + path ไฟล์หลัก + สถานะ merge/push).
- ปรับบรรทัด `⏭️ ถัดไป:` ให้ตรงกับสิ่งที่ควรทำต่อจริง ๆ (งานถัดไป + ของที่ค้าง/follow-up).
- ถ้ามี **การตัดสินใจสำคัญที่ไม่ชัดจากโค้ด** (เลือกแนวทาง/แก้ contract/กติกาใหม่) → เพิ่ม entry ใน
  **Decision log** ด้วย (สั้น กระชับ อธิบาย "ทำไม" ไม่ใช่แค่ "อะไร").

## 3. อัปเดต `docs/HANDOFF.md`
- ส่วน **TL;DR — ตอนนี้อยู่ตรงไหน**: เพิ่ม bullet งานล่าสุด + ปรับ "ถัดไป (ยังไม่เริ่ม)".
- ถ้าจำนวนเทสต์/coverage เปลี่ยน → อัปเดตบรรทัดสรุปเทสต์ให้ตรง (`npm test` / integration count).
- ถ้ามีบัญชีทดสอบ/วิธีรัน/กติกาใหม่ → อัปเดตส่วนที่เกี่ยวข้อง (มักคือ §2 วิธีรัน, §3 กติกา).

## 3.5 เอกสารตรวจรับ (ถ้า session นี้แตะโค้ดที่ผู้ใช้ต้องตรวจ)
- ถ้าแตะ `apps/web/src/pages/` · `apps/web/src/components/` · `apps/api/src/*/*.service.ts` · `prisma/schema.prisma`
  → รัน `npx tsx scripts/gen-acceptance.ts --check` แล้ว **เตือนผู้ใช้ว่าหน้าไหนต้องตรวจซ้ำ**
  (เอกสารรายหน้าอยู่ที่ `docs/acceptance/` — สั่ง `/acceptance ที่เปลี่ยน` ให้อัปเดต).
- อย่าปล่อยให้เอกสารล้าสมัยเงียบ ๆ — ระบุใน HANDOFF ว่าหน้าไหนค้างตรวจ.

## 4. งานที่ยังไม่ commit
- ถ้า working tree มีของค้าง: **ระบุใน HANDOFF ให้ชัด** ว่ามีอะไรค้าง อยู่ branch ไหน ทำถึงไหน
  (session หน้าจะได้ไม่งง). แล้วเตือนผู้ใช้ว่า **ควรรัน `/ship`** เพื่อ commit + push ก่อนปิด
  (ถ้าผู้ใช้อยากเก็บขึ้น remote). อย่า commit อัตโนมัติในสกิลนี้ — นั่นเป็นหน้าที่ `/ship`.

## 5. กติกาการเขียน handoff (สั้นแต่พอใช้)
- อย่าเขียนซ้ำสิ่งที่โค้ด/git บันทึกอยู่แล้ว (โครงไฟล์, ประวัติ) — เขียนเฉพาะ **สถานะ + ทำต่อตรงไหน + why**.
- คำอธิบายไทย, ชื่อไฟล์/เทคนิคอังกฤษ (ตามกติกา repo).
- ลิงก์ path ไฟล์จริงให้ session หน้าเปิดตรงได้ (`apps/api/src/...`, `docs/...`).

## 6. รายงานผล
สรุปให้ผู้ใช้: อัปเดตไฟล์อะไรบ้าง, งานที่ค้าง (ถ้ามี) + branch, และเตือนว่าจะ `/ship` เอกสารเหล่านี้ขึ้น
main เลยไหม.
