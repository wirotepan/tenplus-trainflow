# /acceptance — เขียนเอกสารตรวจรับรายหน้า

เป้าหมาย: ให้เจ้าของระบบ **ตรวจ logic เองได้และรู้ว่าจะแก้ตรงไหน**. ผู้ใช้ไม่ถนัด terminal — **รันคำสั่งให้เอง**.
โครงเอกสาร + กติกาที่ใช้ร่วมกันอยู่ที่ `docs/acceptance/_conventions.md` (อ่านก่อนเขียนหน้าแรกของ session).

## 1. ตีความ argument → เลือกโหมด
- `<ชื่อหน้า>` (เช่น `orders`, `/billing`, `27`) → ทำหน้าเดียว
- `ทั้งหมด` → ทุกหน้าที่ยังไม่มีไฟล์ หรือยังมี `<!-- TODO:` ค้าง
- `ที่เปลี่ยน` หรือ **ไม่ใส่ argument** → รัน `npx tsx scripts/gen-acceptance.ts --check` ก่อน แล้วทำเฉพาะหน้าที่ขึ้นเตือน `[E]`/`[F]`
- รายชื่อหน้าทั้งหมด: `npx tsx scripts/gen-acceptance.ts` (ไม่ใส่ flag)

## 2. รัน generator ก่อนเสมอ
- `npx tsx scripts/gen-acceptance.ts --page <slug>` → สร้างไฟล์ (ถ้ายังไม่มี) + รีเฟรชบล็อก `gen:*` ให้สดจากโค้ด
- สคริปต์จะพิมพ์ **รายชื่อไฟล์ต้นทางที่ต้องอ่าน** ออกมา — ใช้รายการนั้นเป็นแผนการอ่าน

## 3. อ่านโค้ดจริงก่อนเขียน (ห้ามเดา)
อ่านให้ครบ: หน้าจอ (`apps/web/src/pages|components/…`) · controller + service + mapper + helper · `prisma/schema.prisma`
เฉพาะ model ที่เกี่ยวข้อง · ไฟล์เทสต์ (ดูว่าอะไรถูกล็อกพฤติกรรมไว้แล้ว — เป็นแหล่งกฎธุรกิจชั้นดี)

## 4. เขียนเฉพาะส่วนของคน (ข้อ 1, 3, 4 เมื่อไม่ใช่หน้า master, 5, 6, 9)
- **ห้ามแตะข้อความในบล็อก `<!-- gen:… -->`** — เครื่องเป็นเจ้าของ แก้แล้วจะถูกทับ
- **ห้ามแก้/ลบ checklist ที่ผู้ใช้ติ๊ก `[x]` ไว้แล้ว** — เพิ่มข้อใหม่ต่อท้ายได้เท่านั้น
- **ทุกกฎในข้อ 6 ต้องชี้ที่มาแบบ `` `path/file.ts` → `symbol()` `` ที่มีอยู่จริง** (ตัวตรวจด่าน C จะจับ)
  หาที่มาไม่เจอ → เขียนว่า `❓ ไม่พบที่มาในโค้ด — ต้องยืนยัน` **ห้ามแต่งกฎเอง**
- ข้อ 4 (หน้าที่ไม่ใช่ master): ทุกแถวต้องมีคอลัมน์จริงในรูป `` `Model.column` `` · หน้าที่ยิงหลาย endpoint
  ให้แตกเป็นตารางย่อยตาม "งานที่ทำ" (เช่น 4.1 ออกบิล / 4.2 รับชำระ) ไม่ใช่ตารางเดียวยาว
- ข้อ 5 คือหัวใจ: ฟิลด์ที่ **ไม่มีคอลัมน์ใน DB** (คำนวณตอนอ่าน) — ต้องบอกสูตรและไฟล์ที่คิด
- ข้อ 9 checklist: เขียนเป็น "สิ่งที่กดทดลองได้จริง + ผลที่ควรเห็น" อย่างน้อย 12 ข้อ ครอบคลุม
  สร้าง/แก้ · เคสขอบ · การเชื่อมกับหน้าอื่น · **สิทธิ์ (role ที่ไม่ควรเห็น)** · isolation ข้ามบริษัท
- ภาษาไทยสำหรับคำอธิบาย · อังกฤษสำหรับชื่อไฟล์/field/คอลัมน์ · **ห้ามใส่ข้อมูลจริงของลูกค้า**
  (ตัวอย่างต้องมาจาก `prisma/seed.ts` หรือ `docs/TEST-ACCOUNTS.md` เท่านั้น — ด่าน G จะจับ)

## 5. หลายหน้า → ใช้ subagent
ถ้าโหมดคือ `ทั้งหมด`/`ที่เปลี่ยน` และมีมากกว่า 2 หน้า → ยิง subagent `acceptance-writer` **ทีละ 3 หน้าขนาน**
จัดกลุ่มตามโมดูลเดียวกัน (เช่น jobs+quotation, booking+calendar, test+certificate) เพื่อให้ใช้ context ร่วมกันได้ · หน้า master
รวบเป็น agent เดียวได้ (ตารางถูก generate ให้แล้ว เหลือแค่ข้อ 1/3/9)

## 6. ตรวจก่อนจบ
- `npx tsx scripts/gen-acceptance.ts --check` → **ต้องไม่มี ❌** (⚠️ ของหน้าที่ยังไม่ทำ ปล่อยได้)
- `npx tsx scripts/gen-acceptance.ts --index --web` → อัปเดตสารบัญ + หน้าเว็บสรุป

## 7. รายงานผล
สรุปให้ผู้ใช้: หน้าที่ทำ · กฎธุรกิจที่พบกี่ข้อ · **ข้อที่หาที่มาไม่เจอ/ไม่แน่ใจ (ให้ผู้ใช้ตัดสิน)** ·
สิ่งที่พบว่าโค้ดอาจผิดระหว่างอ่าน · แล้วบอกว่าเปิดอ่านได้ที่ `docs/acceptance/index.html` และใช้ `/ship` เพื่อ push
