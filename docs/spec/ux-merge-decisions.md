# UX/UI — สิ่งที่รับมาจากงานออกแบบของลูกค้า + สิ่งที่คงของเราไว้

> ที่มา: `docs/spec/uxui.jpg` (ลูกค้าออกแบบ 12 หน้าจอ) · ฟีดแบ็ก: *"ชอบ front เรา แต่ของเราเขียวเกินไป"*
> ผลลัพธ์: `docs/trainflow-prototype-customer.html` (15 หน้า) + `apps/web/src/theme.css` (palette v2)

## 1. ทำไมของเรา "เขียวเกินไป" — สุ่มสีจากงานลูกค้าแล้วเจอคำตอบ

| ส่วน | ของลูกค้า | ของเรา (v1) | แก้เป็น (v2) |
|---|---|---|---|
| พื้นหลังหน้า | `#F0F4F5` เทากลาง | `#F3F7F6` เจือเขียว | `#F4F6F7` เทากลาง |
| พื้นผิวรอง | `#E8ECED` เทากลาง | `#E6EFEC` เจือเขียว | `#E8ECED` |
| เส้นขอบ | เทากลาง | `#E1E9E7` เจือเขียว | `#E1E6E8` |
| ตัวอักษร | เทาเข้มกลาง | `#152420` เจือเขียว | `#161D20` |
| สีหลัก | `#17852F` เขียวใบไม้ | `#0E8C82` teal (เขียวอมฟ้า) | `#17852F` |
| แถบเมนู | `#002917` เขียวเข้มเกือบดำ | ไม่มี | `#002917` |

**ข้อสรุป:** ปัญหาไม่ได้อยู่ที่ "มีสีเขียว" แต่อยู่ที่ **พื้นผิวทุกชิ้นถูกเจือเขียว** ทำให้ทั้งจอเป็นสีเดียว
งานลูกค้าใช้เขียวเฉพาะ 3 ที่ — แบรนด์/แถบเมนู · ปุ่มหลัก · สถานะ "ผ่าน" — ที่เหลือเป็นเทาสะอาด
เราทำตามนั้น และเปลี่ยนจาก teal เป็นเขียวใบไม้ตามแบรนด์ของลูกค้า
เพิ่ม token ใหม่: `--brand-deep` (แถบเมนู) · `--accent-ink` (ตัวอักษรเขียวเข้มให้คอนทราสต์พอ) · `--gold` (วุฒิบัตร)

## 2. ข้อดีจากงานลูกค้าที่รับมาใช้

| # | สิ่งที่รับมา | ทำไมดีกว่าของเดิม |
|---|---|---|
| 1 | **แถบเมนูซ้าย (sidebar) สีเขียวเข้ม** | ระบบนี้มี 14+ เมนู — เมนูบนแนวนอนของเดิมจะล้น และ sidebar ยังเป็นที่วาง **ตัวสลับบริษัท** ของ SaaS ได้พอดี |
| 2 | **หน้าเข้าสู่ระบบพร้อม Google / Microsoft** | ลูกค้าองค์กรมี Microsoft 365 อยู่แล้ว ลดงานจัดการรหัสผ่าน |
| 3 | **KPI 8 ช่อง** (เพิ่ม ต้นทุน · margin · จำนวนวิทยากร · วุฒิบัตรที่ออก) | ของเดิมมี 4 ช่อง ตอบได้แค่ "ทำเท่าไร" ไม่ได้ตอบ "เหลือเท่าไร" |
| 4 | **Wizard สร้างงาน 8 ขั้น** | งานอบรมมีข้อมูลเยอะ การไล่ทีละขั้นลดการกรอกผิดและกรอกไม่ครบ |
| 5 | **แถบขั้นตอนแบบติ๊กถูก + กล่อง "สถานะงาน"** | อ่านง่ายกว่าแถบ 16 จุดของเรา — เราจึงย่อเหลือ 8 ก้อนบนจอ แต่เก็บ 16 ขั้นไว้ในข้อมูล |
| 6 | **กราฟรายได้–ต้นทุน–กำไร + แท่งสถานะงาน** | ผู้บริหารเห็นแนวโน้ม ไม่ใช่แค่ตัวเลขเดือนนี้ |
| 7 | **ตารางผู้เข้าอบรมมีคอลัมน์ เช้า/บ่าย/Pre/Post/ผลการอบรม** | ตรงกับโครงข้อมูลของเราพอดี (เช็คชื่อรายรอบ) และเห็นครบในตารางเดียว |
| 8 | **QR แยก 2 จอ: จอฉายหน้าห้อง + จอมือถือผู้เข้าอบรม** | ตรงกับที่เราออกแบบเรื่องรหัสหมุน 30 วินาที |
| 9 | **หน้าทำข้อสอบมีตารางเลขข้อ + นาฬิกานับถอยหลัง** | ผู้เข้าอบรมรู้ว่าเหลือกี่ข้อ ลดข้อสอบค้าง |
| 10 | **วุฒิบัตรขอบทองแบบทางการ** | ลูกค้าองค์กรคาดหวังหน้าตาแบบนี้ — เพิ่ม token `--gold` ไว้ใช้เฉพาะของที่เป็นเกียรติบัตร |
| 11 | **การเงินแบ่งเป็นแท็บ + โดนัท margin** | อ่านง่ายกว่ายัดทุกอย่างในตารางเดียว |
| 12 | ⭐ **แท็บ "เปรียบเทียบงบ vs ใช้จริง"** | **ของใหม่ที่เราไม่ได้ออกแบบไว้** — ทำให้รู้ว่าหมวดไหนกำลังบานปลาย *ระหว่างจัดงาน* ไม่ใช่มารู้ตอนปิดงบ |
| 13 | **รายงานมีสารบัญ 15 หัวข้อ + ตัวอย่างหน้า** | เห็นว่ารูปเล่มจะออกมาหน้าตาอย่างไรก่อนกดส่งลูกค้า |

> ข้อ 12 ต้องเพิ่มใน `02-system-design.md`: `TrainingJob.budgetJson` หรือ `JobCost.budgetAmount`
> (ตั้งงบต่อหมวดตอนยืนยันงาน แล้วเทียบกับค่าจริง) — **ยังไม่ได้อยู่ใน ER ปัจจุบัน**

## 3. สิ่งที่คงของเราไว้ (งานลูกค้าไม่มี แต่จำเป็น)

| สิ่งที่คงไว้ | เหตุผล |
|---|---|
| **หน้าจองวิทยากรแบบ "เลือกได้ / เลือกไม่ได้ + เหตุผล"** | หัวใจของจุดขายที่ 1 — งานลูกค้าไม่มีหน้านี้เลย มีแต่ปฏิทิน |
| **จองชั่วคราวมีวันหมดอายุ (ถือสิทธิ์ 48 ชม.)** | กันวิทยากรไม่ตอบแล้ววันถูกล็อกค้าง |
| **เหตุผลที่วิทยากรถูกตัดออก** (ติดงาน/ไม่อยู่ในทะเบียน/คุณวุฒิหมดอายุ/แจ้งลา) | ให้แก้ที่ต้นเหตุได้ ไม่ใช่ชื่อหายเฉย ๆ |
| **กติกาสีสถานะแยกจากสีแบรนด์** | เขียว = ผ่าน/ยืนยัน เท่านั้น ห้ามเอาเขียวแบรนด์ไปปนกับเขียวสถานะ |
| **หน้าตรวจสอบวุฒิบัตรสาธารณะแบบเปิดเผยน้อยที่สุด** | ไม่แสดงคะแนน/เลขบัตรประชาชน/ชื่อบริษัทลูกค้า (PDPA) |
| **สถานะสดตอนเช็คชื่อ + ปุ่มโทรตามคนที่ยังไม่มา** | ปัญหาจริงหน้างานคือ "ใครยังไม่มา" |

## 4. ชั้น SaaS ที่เพิ่มเข้ามา (ตามที่สั่งให้เห็นภาพ)

| หน้า | แสดงอะไร |
|---|---|
| **ตัวสลับบริษัทบน sidebar** | 1 ระบบ หลายบริษัท · เห็นชื่อบริษัทและแพ็กเกจที่ใช้อยู่ตลอดเวลา |
| **แพ็กเกจ & การใช้งาน** | Starter / Professional / Enterprise + แถบโควตา (งาน · ผู้ใช้ · พื้นที่) + เตือนก่อนเต็ม |
| **แบรนด์บริษัท** | โลโก้ · สีแบรนด์ · แม่แบบวุฒิบัตร · รูปแบบเลขที่วุฒิบัตร → เห็นตัวอย่างผลลัพธ์ทันที |
| **คอนโซลผู้ให้บริการ** | รายชื่อบริษัทที่เช่าใช้ · MRR · โควตา · วันต่ออายุ · สถานะค้างชำระ/ทดลองใช้ |

หน้าลูกค้าองค์กร · แบบประเมินความพึงพอใจ · หน้าวิทยากรบนมือถือ (มีในต้นแบบรอบก่อน)
